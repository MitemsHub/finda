# The Style Knowledge Base

### A growing library of design references that *teaches* style

> This folder is the living output of [`../51-REFERENCE_ANALYSIS.md`](../51-REFERENCE_ANALYSIS.md). Each file is a structured teardown of a great website, written **principles-first** so the studio learns *why* great design works — never to copy it, always to understand and adapt it.

---

## How to use this library

- **To learn:** browse teardowns to absorb transferable principles (each maps back to our chapters/tokens).
- **To start a design:** run the **"Any References?" protocol** ([`../51-REFERENCE_ANALYSIS.md`](../51-REFERENCE_ANALYSIS.md) §7) — the studio asks you for references, researches its own, analyzes any new ones into this folder, then synthesizes an **original** direction from the combined principles + your brand.
- **To add a reference:** copy [`_TEMPLATE.md`](./_TEMPLATE.md) → `references/<slug>.md`, run the engine, fill all 11 outputs, pass the copying-line test (§8), add front-matter + tags.

## The copying line (non-negotiable)

Every teardown must **PASS** the four-part test in [`../51-REFERENCE_ANALYSIS.md`](../51-REFERENCE_ANALYSIS.md) §8:
1. The source's team would **not** recognize their specific work in ours.
2. We synthesized from **multiple** sources + our own brand.
3. Every choice is explained by a **principle**, not "because they did it."
4. All assets (logos, fonts, images, icons, copy) are **ours or licensed**.

We extract **principles**, never pixels, trademarks, fonts, photography, or copy.
